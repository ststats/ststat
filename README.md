# 캄몬라이더 자동 병목 비교

## 실행
ZIP을 풀고 `.github`와 `perf` 폴더를 테스트할 GitHub 저장소 루트에 올립니다. 숨김 폴더 `.github`도 포함해야 합니다.
Actions → Rider automated comparison → Run workflow를 한 번 실행합니다.
버튼 전환, 선수 추가, 경기 시작, 기록 저장은 전부 자동입니다.
완료 후 Actions의 `rider-...` 아티팩트를 다운로드해 전달하면 됩니다.
별도 웹사이트 배포는 필요 없습니다. 포함된 game.html을 GitHub 러너 내부에서 실행합니다.

## 조건
- graphics: 원본 / 단색 메인 화면 / 모든 캔버스 그리기 중지 / 출력 70% / 출력 125%
- layers: 원본 / 트랙 대신 단색 / drawEffects와 피격 표현 생략 / 이름표 생략 / 미니맵 생략
- activity: 원본 / updateUI 생략 / 소리 끄기 / 전체 카메라 / 고정 카메라
- pipeline: 원본 / 30fps 제한 / 카트 생략 / 차체 캐시 대신 벡터 / 얼굴 생략

17개 고유 조건이며 그룹마다 원본을 재측정합니다. 효과 생략은 부스터 불꽃·실드 등 drawKart 안의 모든 장식을 제거하는 조건은 아닙니다. UI 생략도 이벤트 알림 등 모든 DOM 쓰기를 중단하는 것은 아닙니다.
PC(1280×900) / 모바일 크기(390×844), 8명 / 48명, 3회 반복입니다.
16개 작업, 작업당 15회, 총 240회, 각 45초를 측정합니다. 최대 4개 작업을 병렬 실행하므로 전체 약 45분 이상, 합계 약 180 러너 분 이상이 필요합니다. GitHub 계정의 Actions 사용 한도가 적용됩니다.
매회 새 브라우저 컨텍스트와 같은 난수 시드를 사용합니다. 반복마다 조건 순서를 순환해 고정 순서 영향을 줄입니다. 통계는 CPU 프로파일 샘플링 없이 trace 이벤트로 집계합니다.

## 결과
각 작업에 summary.json, 회차별 trace.json, 마지막 스크린샷을 저장합니다.
Commit / FireAnimationFrame / GC의 횟수, 95백분위, 최대, 50ms 초과 횟수 및 실제 캔버스 크기를 기록합니다.
원본 파일 SHA256과 Chromium 버전도 남깁니다. 실패 시 성공한 결과까지 업로드합니다.

## 해석 제한
GitHub Linux headless Chromium은 사용자 Windows GPU 환경과 다릅니다. 모바일은 화면 크기만 변경하며 실제 휴대폰이 아닙니다. 여기서 지연이 재현되지 않는다면 사용자 환경에서 해결되었다고 결론내릴 수 없습니다.
고정 카메라나 효과 제거는 병목 분리를 위한 진단 조건이며 제품 변경안이 아닙니다.
프레임 제한·카메라 조건은 시뮬레이션 진행 시점에도 영향을 줄 수 있으므로 순위 자체를 성능 점수로 비교하지 않습니다.

현재 검증: 실행 스크립트 문법, 17개 조건의 48명 모의 초기화·tick·render 통과. 실제 GitHub 실행은 아직 하지 않았습니다.
